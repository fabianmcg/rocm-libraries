## Milestone 3 — Float8 Data Types (OCP and fnuz variants)

**Executed by:** fresh implementor agent
**Reviewed before:** Milestone 4 begins

### Goal

Add references and tests for all four fp8 variants. Verify `ml_dtypes` semantics match the
compiled kernel's semantics.

### Tasks

**3.1 — Kernel semantics introspection**
Before implementing references: read each test kernel's YAML `ProblemType` to confirm
whether it was compiled with `HIP_FP8_TYPE_OCP` or `HIP_FP8_TYPE_FNUZ` (check the
`DataType` integer field). Use the following mapping (from `Tensile/Contractions.py` —
check `isFloat8BFloat8()` vs `isFloat8BFloat8_fnuz()` for the authoritative list):

| DataType int | Name | OCP or fnuz | `ml_dtypes` equivalent |
|---|---|---|---|
| 11 | Float8_fnuz (E4M3) | fnuz | `ml_dtypes.float8_e4m3fnuz` |
| 12 | BFloat8_fnuz (E5M2) | fnuz | `ml_dtypes.float8_e5m2fnuz` |
| 15 | Float8 (E4M3) OCP | OCP | `ml_dtypes.float8_e4m3fn` |
| 16 | BFloat8 (E5M2) OCP | OCP | `ml_dtypes.float8_e5m2` |

Fail loudly (`assert False, f"unknown fp8 DataType: {dtype_int}"`) if the integer is not in
this table. Cross-check the table against `Tensile/DataType.py` before using it.

**3.2 — Float8 reference**
- `gemm_fp8(A, B, dtype_a, dtype_b, dtype_out, ...) -> np.ndarray`: upcast both to float32
  via `ml_dtypes` cast, matmul, downcast to `dtype_out`.
- NaN encoding unit test (no GPU): verify `ml_dtypes.float8_e4m3fn` has NaN at bit pattern
  `0x7F`, `float8_e5m2` has NaN for patterns `> 0x7C`, `float8_e4m3fnuz` / `float8_e5m2fnuz`
  have NaN at `0x80`. Matches `DataTypes_Float8_BFloat8.hpp:407–490` (the `isnan`/`isinf`/`iszero` functions for OCP at 407–430 and fnuz at 463–490).

**3.3 — Extend `build_kernel_args`** for fp8 input/output dtype branches, including the
`compute_input_type_A/B` argument slots.

**3.4 — Write `test_gemm_fp8.py`**
- Four dtype combinations: E4M3 OCP, E5M2 OCP, E4M3fnuz, E5M2fnuz.
- Sizes: (256,256,256), (512,512,512), (1024,1024,1024).
- NaN propagation test per variant: seed one A element with NaN, verify GPU D contains NaN.
- Poison-input test per dtype.

**3.5 — OCP vs fnuz cross-validation**
If both builds are available, run the same problem on C++ client with each fp8 type and
compare. Document which YAML kernels use which flavor.

### Acceptance criteria
- NaN bit-pattern test passes in pure Python (no GPU).
- Kernel semantics introspection step correctly identifies OCP vs fnuz for all test kernels.
- All `test_gemm_fp8.py` tests pass on gfx950.
- No regressions.
